How NetPulse Works

A transparent look at the methodology, accuracy limits, and privacy model behind this test.

Download & Upload

NetPulse downloads and uploads randomly-generated data to Cloudflare’s public speed-test endpoints (speed.cloudflare.com/__down and /__up), the same infrastructure that powers speed.cloudflare.com.

To saturate fast connections, the test opens multiple parallel connections (configurable in Settings) and steps through increasing payload sizes — from ~100 KB up to 100 MB — so slow connections aren’t stuck waiting on huge downloads, while fast connections get enough data to reach their true ceiling.

The headline number is the median of all measured rounds, which resists distortion from a single slow or lucky round. Average, minimum, and maximum are also shown for transparency.

Ping & Jitter

Latency is measured by timing repeated requests to the same edge server’s /cdn-cgi/trace endpoint, which returns a tiny plaintext response almost instantly. This round-trip time approximates ICMP ping, since browsers cannot send raw ICMP packets.

Jitter is the average absolute difference between consecutive ping samples — a measure of how consistent your connection’s latency is. High jitter can cause stuttering in video calls and games even when average ping looks fine.

Packet Loss (Estimated)

Browsers cannot measure true packet loss because JavaScript has no access to raw ICMP/UDP sockets. As an approximation, NetPulse fires many small concurrent HTTP requests with a tight timeout (800 ms) and counts how many fail or time out.

Treat this figure as a rough signal, not a lab-grade packet loss measurement — TCP retransmission and browser connection pooling can both mask or exaggerate real loss.

Server Selection

Before each full test, NetPulse pings every known server and automatically picks the one with the lowest median latency, mirroring how commercial speed tests choose a “nearest” server. You can override this in the dropdown on the home page or pin a default in Settings.

All current servers route through Cloudflare’s anycast network, so “location” differences mostly reflect which data center your ISP’s routing sends you to, not a literal city choice.

Accuracy Limitations

Browser-based speed tests are inherently less precise than dedicated native applications or ISP-side measurements. Known limitations include:

  • Single measurement point. You’re measuring the path to Cloudflare’s edge, not necessarily your ISP’s backbone or a specific destination you care about.
  • Browser/OS overhead. JavaScript garbage collection, tab throttling, and OS network stack behavior all add noise that native tools avoid.
  • TCP ramp-up. New connections take a moment to reach full throughput (TCP slow start), which is why NetPulse uses parallel connections and multiple size steps rather than one huge single-threaded transfer.
  • Local network conditions. Wi-Fi congestion, router CPU limits, VPNs, and other active devices on your network can all suppress results below your plan’s true ceiling.
  • CDN vs. ISP routing. A very fast result to Cloudflare doesn’t guarantee equally fast performance to every other service you use.

For the most representative reading: use a wired Ethernet connection, close other apps and tabs, disable VPNs, and run the Full Test mode a few times at different times of day.

Privacy & Data Storage

NetPulse has no backend, no database, and no analytics tracking beyond what your browser does by default when contacting Cloudflare’s public endpoints and the IP-lookup API.

  • Test history is stored only in your browser’s localStorage, under your device. It never leaves your machine and is not visible to us.
  • Settings and theme (units, thread count, duration, dark/light mode) are likewise stored only in localStorage.
  • Network Info panel calls the free ipapi.co API directly from your browser to show your public IP, approximate location, and ISP. This request goes straight from your browser to ipapi.co — it does not pass through any server we control.
  • Shareable links encode your result numbers directly into the URL fragment (after the #). Nothing is uploaded to generate a share link; the data lives entirely in the link itself.

Clearing your browser’s site data for this page, or using the “Clear All History” button on the History page, permanently deletes all stored results.

Quality Score

The 0–100 “connection quality score” shown after each test is a simple weighted heuristic (download 40%, upload 20%, ping 25%, jitter 10%, packet loss 5%) meant as a friendly, at-a-glance summary. It is not an industry-standard metric — use the raw numbers above it for anything that requires precision.
